# 高校与自定义目录

网站首版开放静态学校资料与本机制作目录包。页面以 `data-online-catalogs="false"` 关闭在线投稿、审核和订阅入口，不发送目录 API 请求。在线功能仍需先执行数据表迁移并部署 API，再启用页面开关。插件文件导入实现已在开发构建验证，当前官网下载包和商店版本未因此替换或改号。

## 免费服务与访问负载

学校及自定义分级采用“下载一次，本机匹配”。浏览器插件与 Zotero 使用同一种目录包；导入文件固定为本地快照，不做远程目录版本检查。直接勾选的订阅目录保留错峰版本检查。两种方式分别保存；本地匹配不需要上传论文、文库或用户的自定义表格。

资料库目前汇集38所学校的47份目录。首批6所高校的8份目录提供标准下载包，共11,773条具名记录，按原等级、学科与适用范围保留。西北农林科技大学食品学院的A刊101条与B刊55条合并为一份156条的指导目录，保留A/B等级及两份原件的来源与哈希；不再按等级拆成两个下载入口。其余39份标为“待用户上传标准目录”，只保留官网来源，等待用户提供；扫描件、仅规则和来源受限文件不自动转成分级。页面不再把原件压缩包作为目录下载。

静态索引是 `assets/catalogs/library-index.json` 与 `standard-index.json`。维护时执行 `python scripts/build-standard-catalogs.py`：只读私有归档的具名转录及原件，对照对外经贸29个中文及19个外文学科的原公布条数修正换行标题归属；按明确标记区分会议与期刊，会议不使用论文集ISSN匹配；校验刊号，同刊同范围同等级合并，排除集合规则与官方暂剔除名单。保留原刊号问题、合并及排除记录。原件SHA-256和官网来源写入包内。`--prepared`可在原件哈希和学科计数检查不变时重用已核对的中间数据。

标准包位于 `downloads/catalogs/standard/`，每份包含统一列名的Excel和可导入的`.journal-scout.json`、整理说明及整理记录。总计14个分册，按原表学科边界拆分；单册不超过5000行、JSON不超过900KB。所有Excel行都经共享校验器回读，并与对应JSON逐字段比较；集合规则、重复项和排除项不假称为新增期刊。旧`references/`和食品学院分开的A/B下载文件仅保留历史地址，不再出现在目录下载入口。线上投稿后台仍未启用。

构建与目录测试需要 Python 的 PyMuPDF、openpyxl，以及 Node.js；原件与私有转录文件不随公共站点脚本发布。

资料库采用左侧高校分类、顶部搜索和逐份目录的书目布局；985 与非985的211高校分开，其他高校暂无资料时显示空状态。搜索与制作按钮在桌面和手机上同行同高；搜索框只保留一层圆角边框。搜索和分类组合在本机完成，可下载目录优先展示。封面标识记录于 `assets/catalogs/university-logos.json`，复用 ScanSci logo 库已发布的 WebP 静态地址并延迟加载，不逐校调用解析 API；34所为独立校徽，另4所保留库中已有的完整校名组合或字标，不把它们标为独立校徽。

如果有1,000名用户各浏览100篇论文，只计算学校标签：每人首次选择一份目录最多下载1份完整文件，100,000次标签匹配均在本机，不对应100,000次学校目录查询。网站普通期刊搜索、通用IF/JCR识别的现有接口不在这个零逐篇请求范围内，继续使用已有服务端共享缓存。

默认交互保持简单：搜索学校 → 查看版本/适用学院 → 一键启用。下载后手动导入为备用方式，自定义目录可以只在本机制作并导入；愿意公开贡献时再提交审核。不做目录交易、支付、订单或“我的/共享”分栏。

## 用户流程

- 网站 `catalogs.html` 提供统一目录搜索、勾选、上传和审核入口。没有“我的目录 / 共享目录”分页。
- 上传者使用已有 ScanSci 账号登录，填写目录资料并上传 XLSX / UTF-8 CSV。在本机解析和预览，通过检查后提交原文件及标准化记录，待管理员审核后公开。
- 无需登录即可填写目录资料、读取 XLSX/CSV、检查预览并下载本地目录包。两种插件的“高校与自定义目录”设置均支持导入。仅公开投稿需要登录。
- 表格至少包含“名称、等级”。会议必须标明类型；ISSN/eISSN、简称、适用范围和备注可留空。模板下载位于 `assets/templates/catalog-upload-v1.xlsx`。
- 每份目录最多5,000行，原文件1MB，标准化记录900KB；最多同时启用10份。较大的目录可按明确的适用范围拆分。
- 管理员登录同一页面、展开上传区域后可见待审核列表，可以下载原文件和标准化名单，填写备注并通过或退回。公开列表缓存最长5分钟；审核者会立即看到已通过的目录。
- 网站选择保存在该浏览器。新版浏览器插件会通过仅限本网站目录页的连接接收选择；Zotero 在「设置 → Journal Scout → 高校与自定义目录」中搜索并勾选。两端的选择分别保存，不上传用户文献或全文。

## 分级和匹配

学校原等级原样保留，与 JCR、CCF 等独立显示。优先按标识和完整刊名匹配，不做宽泛模糊推测；标识冲突、重复名称/别名需要修正。会议支持完整名称及明确简称，无需 ISSN。规则说明只作为文字，不执行上传表里的代码或公式。

学校、目录名称和适用范围构成稳定目录 ID；同一目录的不同年份/内容修订有不同版本。更新时保持目录名称与范围一致，在“目录版本”中填写新年份。旧版本包保持可访问。插件每天错峰检查已选目录的新版本，离线保留上次成功下载的目录。

Zotero 自定义分级保存在独立本地目录包中，仅参与显示；不会覆盖通用指标、写入原生标签或参与现有数字指标搜索。切换目录不修改文献条目。复杂的毕业/聘任资格认定仍需核对规则与原始文件。

## API 与保存

API 位于 `scansci-portal-repo/worker/src/journal-catalogs.js`，复用现有账号、管理员权限及 D1 `DB` 绑定。

- `GET /api/journal-catalogs?q=&offset=`：已发布目录摘要，50条分页，5分钟共享缓存。
- `GET /api/journal-catalogs/:id`：当前发布版本摘要，5分钟共享缓存。
- `GET /api/journal-catalogs/:id/versions/:version`：不可变公开数据包，长期缓存。
- `POST /api/journal-catalogs`：登录后提交标准化目录及原文件，默认待审核；有来源校验和提交额度限制。
- `GET /api/journal-catalogs/account`：当前账号最近提交状态与管理员身份，不缓存。
- `GET /api/journal-catalogs/review`、`GET /review/:version/preview`、`GET /review/:version/source`、`POST /review/:version`：管理员审核接口，不缓存。

原文件、目录版本和目录索引分别保存在三张新增表中。待审核内容及原文件不会从公开接口返回。原文件仅供管理员核查。新版本审核通过才切换公开指针，旧包不被改写。每篇论文的分级匹配在本机完成，不增加逐篇 API 请求。

待授权上线时，在 worker 项目执行新增迁移 `sql/0021_journal_catalogs.sql`，无需修改期刊主数据库。部署前核对目标仍为现有 `scansci_auth`，不要将整套旧迁移重复应用到线上。

## 维护

`scansci-browser/src/catalogs.js` 是共享校验与匹配代码的源文件，网站 `catalogs-core.js` 与 worker `src/catalogs-core.js` 为分发副本；浏览器的 `catalogs.test.mjs` 检查副本一致。SheetJS 0.20.3 mini 为本地静态依赖，仅上传 XLSX 时加载，许可证保存在 `assets/vendor/SHEETJS-LICENSE.txt`。

浏览器使用开发构建 `npm run build`；Zotero 使用 `scripts/build-zotero.ps1`。构建不等于正式发布，不覆盖官网下载包，不自动提交商店。

验证包括实际 SQLite 的提交/审核/权限/版本测试，共享解析与匹配测试，浏览器核心回归，以及 Zotero 离线显示、停用和重启测试。另用本地隔离 SQLite 跑过 XLSX → 预览 → 提交 → 审核 → 勾选 → 期刊与会议匹配的浏览器操作，桌面和390px手机页面无横向溢出。截图为本地样例，不表示目录已经上线。
